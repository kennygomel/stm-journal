# Журнал рейсов — Telegram-бот + Mini App

Бот и Mini App для учёта рейсов грузоперевозок: каждый водитель ведёт свой журнал,
админ управляет заказчиками и тарифами, доступ выдаётся по заявке.

- **Бот:** @-бот проекта, привязанный через `tgcloud login`.
- **Mini App:** <https://app8888287323.tgcloud.ai/>
- **Админ (владелец):** Telegram ID `323173181`

## Как это работает

### Доступ
1. Новый пользователь пишет боту `/start` — создаётся заявка.
2. Бот отправляет **админу** сообщение с запросом и кнопками «✅ Одобрить» / «❌ Отклонить».
3. После решения пользователю приходит уведомление, и ему открывается Mini App.
4. Пока заявка не одобрена, ни журнал, ни эндпоинты недоступны.

Админы: Telegram ID из `tgcloud/lib/config.js` (`ADMIN_IDS`, по умолчанию `323173181`)
плюс все, кому в Mini App выдали права (раздел «Пользователи»).

### Журнал (пользователь)
Запись содержит: **дату, заказчика, количество точек, пробег, часы** и **readonly-доход за рейс**.
Форма запоминает последнего выбранного заказчика и показывает расшифровку дохода до сохранения.
Доступны создание, редактирование и удаление своих записей; чужие записи недоступны.

### История и баланс
Раздел «История»: доход за выбранный период (этот/прошлый месяц, 7/30 дней, год, всё время
или произвольный диапазон), количество рейсов, точек и пробега, разбивка по заказчикам и по дням.

### Роли

| Роль | Что может |
|------|-----------|
| Владелец (`OWNER_IDS`, по умолчанию `323173181`) | всё: тарифы, заказчики, пользователи и админы |
| Админ | только справочник заказчиков |
| Пользователь | только свой журнал |

Владельца нельзя заблокировать или разжаловать; снять права у самого себя тоже нельзя.

### Панель управления

- **Тарифы и доплаты** (владелец) — базовая ставка по умолчанию, лимиты и доплаты
  за точки, километры, часы и дни месяца. Все доплаты **глобальные**.
- **Заказчики** (владелец и админ) — название и своя базовая ставка;
  пусто → берётся общая ставка по умолчанию.
- **Пересчёт записей** (владелец) — применяет действующие тарифы к прошлым рейсам
  за выбранный период. Сначала показывает предпросмотр: сколько записей изменится,
  как поменяется баланс и по каким журналам; запись — только по кнопке.
- **Пользователи** (владелец) — заявки на доступ, блокировка, роли (админ/пользователь).

## Формула расчёта

```
доход = база(заказчик или общая)
      + max(0, точки − 12) × 2 ₽                    ← за каждую точку сверх лимита
      + max(0, км − 300) × 0,20 ₽                   ← за каждый километр сверх лимита
      + floor(max(0, часов − 8) / 4) × 20 ₽         ← за каждые полные 4 часа сверх лимита
      + 20 ₽, если в календарном месяце ≥ 25 рабочих дней
```

- По точкам и километрам доплата идёт **за каждую единицу** сверх лимита.
- По часам доплата **шаговая**: 20 ₽ за каждые **полные 4 часа** свыше лимита (8 ч).
  `12 ч → +20 ₽`, `16 ч → +40 ₽`, `20 ч → +60 ₽`; `11 ч → 0`, `13 ч → +20 ₽`.
- Доплата только **за превышение**: ровно 12 точек, ровно 300 км или ровно 8 часов —
  без надбавки. Все лимиты и доплаты глобальные, настраивает владелец;
  у заказчика задаётся только его базовая ставка.
- **Доплата за дни** считается по календарному месяцу: 20 ₽, если рабочих дней
  (разных дат рейсов) набралось не меньше 25. Входит в доход **ровно один раз** —
  в последнюю запись месяца; при добавлении, правке и удалении записей позиция
  пересчитывается автоматически. В отчёте показывается отдельной суммой.

Значения по умолчанию: база `120 ₽`, 12 точек, 2 ₽ за точку, 300 км,
20 коп. за километр, 8 часов, 20 ₽ за каждые 4 часа сверх лимита.

Правило часов живёт в двух местах — `tgcloud/lib/calc.js` (сервер) и
`src/hours.js` (клиент), потому что модули `tgcloud/` не видят `src/`.
Совпадение реализаций проверяет тест «правило часов совпадает на клиенте и на сервере».

**Тарифы фиксируются в записи.** Доход и ставки сохраняются на момент рейса,
поэтому более поздняя правка тарифов не переписывает историю. При редактировании
записи доход пересчитывается по действующим ставкам.

## Бренд и тема оформления

**Палитра** взята из `logo.svg` (волновой знак СТМ):

| Токен | Цвет | Откуда |
|-------|------|--------|
| `--brand-light` | `#64C3E5` | светлая волна |
| `--brand-mid` | `--accent`, `#1F94BF` | средняя волна |
| `--brand-deep` | `#37576D` | тёмная волна |
| `--brand-ink` | `#142F46` | текст «STM» |

Тёмная тема растёт из глубокой воды: фон `#0B1B2B`, поверхности `#12293D`/`#17324A`,
акцент `#3FB0D8`.

**Тема Mini App** переключается кнопкой в шапке: `light` · `dark` · `system`
(«как в системе» следит за `prefers-color-scheme`). Выбор хранится за пользователем
(`users.theme` через эндпоинт `saveTheme`) и дублируется в `localStorage`, чтобы
не было вспышки при запуске. Тема Telegram на палитру не влияет — бренд важнее;
цвет шапки Telegram подгоняется под выбранную тему.

**Знак без текста**:

| Файл | Что это |
|------|---------|
| `logo.svg` | исходный логотип (знак + текст), только для разработки |
| `public/brand/stm-mark.svg` | знак без текста, вектор, для вёрстки |
| `public/brand/stm-mark-512.png` | знак без текста, PNG 512×512 |
| `tools/make_brand_mark.py` | генератор этих файлов из `logo.svg` |

Пересобрать знак после правки логотипа:

```bash
python3 tools/make_brand_mark.py
```

## Иконки показателей

Сводки («Доход за период», «Баланс за период») показывают цифры **иконками**, без
текстовых подписей: фургон — рейсы, метка — точки, маршрут — пробег, часы — время.
Единицы измерения остаются в значении (`500 км`, `14 ч`).

Иконки лежат в [src/icons.js](src/icons.js): авторские SVG, сетка 24×24,
`stroke="currentColor"`, один штрих 1.7 — наследуют цвет текста и масштабируются
без потерь. Юникод-глифы и эмодзи не используются.

Посмотреть глазами (юнит-тест проверяет только структуру):

```bash
python3 tools/preview_icons.py   # → tools/icons-preview.png
```

## Знак белорусского рубля

Суммы рисуются знаком из шрифта НБРБ, а не символом `₽`:

- `public/fonts/` → `@font-face { font-family: 'nbrb'; unicode-range: U+E901; }` в
  начале `src/styles.css`; файлы раздаются с `/fonts/…`.
- `unicode-range: U+E901` — шрифт подгружается только для самого знака (область
  PUA), обычный текст остаётся системным шрифтом.
- `fmtMoney()` в `src/format.js` возвращает список узлов: текст суммы + `<span class="nbrb-icon">`
  с кодом `\uE901`. Поэтому суммы вставляются как `el('div', {}, fmtMoney(x))`,
  а не через `text:`.
- Для подписей полей есть `fieldNodes(['Доплата за точку, ', bynSign()], …)`.

Важно: в самом шрифте есть только контур знака (`U+E901`); латинские `B/N/Y`
замаплены на пустые глифы, а лигатура собрана из нестандартной
последовательности — поэтому используется именно код `U+E901`, а не лигатура
`BYN`. Если шрифт не загрузится, знак может отрисоваться пустым квадратом;
число при этом остаётся читаемым.

## Разработка и деплой

```bash
npm install
npm run build      # сборка Mini App в dist/
npm run deploy     # build + push (код, статика)
npm run migrate    # применить изменения схемы БД (интерактивно; --yes без вопросов)
npm run status     # что изменено локально
npm run run -- endpoints/me '{}' --ctx '{ initData: { user: { id: 323173181 } } }'
npm test           # тесты логики на моке платформы (26 проверок)
npm run test:ui    # сборка + smoke-тест интерфейса Mini App в поддельном DOM
npm run test:overflow  # сборка + замер горизонтального скролла в headless Chrome
```

Важно: `push` не трогает базу. После правки `tgcloud/schema.js` нужен `npx tgcloud migrate`.
`push` также печатает URL Mini App и предупреждает, если схема расходится с облаком.

## Тесты

- `npm test` — мок платформенного SDK (`tests/fake-sdk.mjs`): заявка и одобрение доступа,
  расчёт дохода, права, CRUD записей, отчёты, переопределения тарифов заказчика.
- `npm run test:ui` — собранный бандл исполняется в поддельном DOM с фейковым
  `Telegram.WebApp`: проверяется рендер журнала, формы рейса с предпросмотром дохода,
  истории и админ-разделов.

## Интерфейс

- **Дашборд на главной админки**: пользователи, журналы, записи и доход за месяц,
  список журналов с последней датой и блок «Управление» внизу. Данные — из
  `endpoints/adminStats` (только владелец).
- **Стрелка «назад»** вместо лого в подразделах админки: возвращает в панель.

- **Навигация внизу.** «Журнал», «История», «Админ» живут в нижнем баре с иконками:
  шапка остаётся бренду и выбору темы, а до кнопок достаёт большой палец.
  У «Админа» появляется счётчик новых заявок.
- **Короткие заголовки** в админ-разделах («Тарифы», «Пересчёт»): возврат — кнопкой «Назад» в шапке Telegram или вкладкой «Админ» в нижнем баре, без дублирующих крошек.
- **Поля с префиксом**: в фильтрах дат и компактных формах подпись стоит внутри
  рамки слева от значения (`с 01.10.2026 · по 31.10.2026`), а не столбиком сверху.
- **Время рейса — два режима**: «Часами» (одно поле) или «Начало / конец»
  (два поля времени, часы считаются сами; переход через полночь учитывается,
  неполный час отбрасывается). В записи по-прежнему хранится целое число часов.
- **Плейсхолдеры вместо пустоты**: «Новых заявок нет», «Справочник пуст» и т. п.
  с подсказкой, что делать дальше.
- **Мягкие края у горизонтальных лент**: у пресетов и фильтров затухание
  в прозрачность **с обеих сторон** (`mask-composite: intersect` для двух
  градиентов). У самого начала или конца ленты соответствующая сторона
  перестаёт гаситься — классы `at-start` / `at-end` вешает `scrollFade()`.

## Проверка раскладки (горизонтальный скролл)

`npm run test:overflow` поднимает `dist/`, подмешивает заглушку `Telegram.WebApp`
(настоящий SDK с telegram.org перехватывается через CDP `Fetch`, иначе он обнуляет
`initData` вне Telegram), гоняет headless Chrome на ширинах 320–1280 и меряет
`scrollWidth` документа на каждом экране: журнал, форма рейса, история, админка.

Что нашлось и как исправлено: длинные неразрывные значения (сумма вида
«1 234 567 ₽», длинное название заказчика) расширяли страницу. Причина — flex- и
grid-элементы по умолчанию имеют `min-width: auto` и не сжимаются ниже
`min-content`, а `.amount` вдобавок стоял с `white-space: nowrap`. Исправлено:

- `min-width: 0` у грид-элементов `.journal-top` и у сумм/подписей в строках;
- `overflow-wrap: anywhere` / `word-break: break-all` для сумм и длинных названий;
- `.list-row .amount` и `.trip-amount` могут переноситься, если строка не влезает.

## Известные ограничения

- Знак BYN зависит от загрузки шрифта `/fonts/nbrb.woff2` (при сбое — квадрат вместо знака).

- База — SQLite без внешних ключей (особенность платформы); целостность
  обеспечивается кодом: записи журнала хранят снимок имени и ставок заказчика,
  поэтому удаление заказчика не ломает историю.
- Записи датируются днём (без времени); часы — это длительность рейса, целое число.
- Владелец определяется списком `OWNER_IDS` в `tgcloud/lib/config.js` (или переменной `ADMIN_IDS`).
- Валюта — белорусские рубли; суммы отображаются как `₽`.
